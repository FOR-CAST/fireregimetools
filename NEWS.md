# fireregimetools (development version)

# fireregimetools 0.1.1

- `filter_fire_records()` keeps the fire records of the given cause groups and drops prescribed burns, the records a fire model is compared with. `fire_cause_group()` and `is_prescribed_burn()` are the two tests it applies. The groups (natural, human, unknown, other) cover the cause values of NBAC (`FIRECAUS`) and of each NFDB release (`CAUSE`, and from the 2026 points `CAUSE2`), including NFDB's `n/a` and `Re`; a value outside them is an error. The loaders already keep these columns.
- The fire-record loaders (`load_nbac_polys()`, `load_nfdb_polys()`, `load_nfdb_points()`) now accept `study_area = NULL`, which returns the harmonised records whole, in their source CRS, neither projected nor cropped. A caller that subsets by its own geometry downstream -- rather than by one study area here -- would otherwise have to reimplement the read, the tolerant year/size column harmonisation and the year/size filters purely to avoid the crop. The spatial pre-filter is off for such a call, there being no footprint to push a filter down against.
- `fetch_nfdb_polys()` and `download_fire_records()` gain `include_pre1972`, which additionally fetches the separate pre-1972 NFDB fire-polygon archive. CWFIS splits that record: `current_version/NFDB_poly.zip` carries 1972 onward only, and the earlier fires live in `NFDB_poly_pre1972.zip`, so a project whose window reached before 1972 silently got no perimeters for those years -- and a per-project extract pattern naming the 1972-onward partitions excluded them twice over. It is `FALSE` by default because those earlier fires are the record's least reliable part: the NFDB documentation claims no accuracy for its own perimeters, and where CNFDB mapping has been checked against satellite imagery it ran high -- retroactive Landsat mapping of Northwest Territories fires cut the historical estimate by 3 Mha (16%), and CNFDB annual burned-area estimates carry confidence intervals about three times the width of NBAC's (Skakun et al. 2022, doi:10.3390/rs14133050). Pre-1972 is wholly pre-satellite, so they are opted into deliberately rather than inherited; `load_nbac_polys()` documents the comparison. The second archive caches in a SIBLING of `dest` rather than inside it: the main archive's pattern `NFDB_poly_.*\.shp$` also matches a pre-1972 shapefile and the cache check tests the pattern before the per-URL stamp, so a shared directory holding only the pre-1972 extraction would make the main record look cached and it would never be fetched (a subdirectory does not help, since the file search falls back to a recursive match when nothing matches at the top level). NBAC is unaffected -- the composite itself begins in 1972 -- and the NFDB *point* record is not split by year.
- `download_fire_records()` exposes the download half of the `fetch_*()` family on its own, returning the extracted shapefile paths and leaving the reading to the `load_*()` functions. The `fetch_*()` functions do both in one call, which forces a caller that wants to cache the archive separately from the per-study-area load -- a `{targets}` `format = "file"` target, for instance -- to reimplement the download. The archive URLs and extract patterns now live in one internal table that both entry points read, so they cannot drift apart.
- Requires R (>= 4.4), raised from 4.1, to use base `%||%`. Supporting older releases costs more than it returns for a package whose consumers all run a current R.
- The fire-record loaders' spatial pre-filter now builds its box from the study area's outline densified along straight lines in the study area's own CRS -- how `terra::crop()` draws the edges -- replacing a filled grid of sample points (from #1, by @eliotmcintire, which also contributed a regression test for a record just inside a curved lon/lat edge). Projecting only the corners misses such a record, and so does `terra::project()` on a `SpatExtent`, which densifies along great circles. The pre-filter now also declines, reading the source whole, when a lon/lat source's longitudes wrap -- a study area containing a pole or straddling the antimeridian -- since no box around the outline can be trusted there. The records returned are unchanged.
- The fire-record loaders (`load_nbac_polys()`, `load_nfdb_polys()`, `load_nfdb_points()`) and their `fetch_*()` wrappers now push the study-area filter down to the GDAL/OGR read, so only records near the study area are materialised in R: the source is opened as a proxy (no geometry read), the study area's footprint is projected into the records' CRS as a padded bounding box, and only the features inside it are read -- geometry repair, projection and the crop then see a study-area-sized subset instead of the whole national record (the NBAC shapefile alone is ~1.9 GB for Canada). The records returned are unchanged: the box is a deliberate superset, `terra::crop()` still makes the exact selection in the study area's own CRS, and every step falls back to reading the source whole. Set `options(fireregimetools.prefilter = FALSE)` to read the sources whole regardless.
- Archive acquisition now replaces files portably: Windows refuses to rename onto an existing file, and a handle left open by a failed read of a truncated archive can outlive the `unlink()`, so a re-download could fail with "cannot rename ... Access is denied" instead of replacing the bad copy.
- The fire-record loaders now check for a missing CRS up front and say which argument is at fault. `terra::project()` already rejects an empty CRS, but only after every shapefile has been read and repaired (minutes and ~1 GB of I/O for the national records), and its message names neither the study area nor the offending file.
- The fire-record loaders now preserve the harmonised `YEAR` + `SIZE_HA` schema when no record survives the crop; `terra::crop()` returns an attribute-less `SpatVector` in that case, so callers reaching for `$YEAR` previously got `NULL` rather than an empty vector.
- The loaders' documentation now states the two crop semantics that were only implicit: a **vector** `study_area` selects records by its geometry while a **`SpatRaster`** selects by its extent (its `NA` cells do not narrow the selection), and a perimeter clipped at the study-area boundary keeps the full reported `SIZE_HA` alongside its truncated geometry.
- `fetch_nbac_polys()` and `fetch_nfdb_polys()` download + load the NBAC (~1.2 GB) and NFDB fire-polygon (~780 MB) archives, completing the fetch-and-load set alongside `fetch_nfdb_points()`; NFDB polygons ship as several multi-year partitions and all are bound together, and the NBAC default `url` pins a dated release (NBAC filenames are dated, unlike NFDB's mutable `current_version/` path) so re-runs fetch the same data.
- Archive acquisition is now hardened against silent truncation: the download timeout is raised (R's 60 s default truncates these archives rather than erroring), the archive is staged through a `.part` file and renamed only on success, an unreadable (truncated) cached archive is re-downloaded, and an extraction is verified file-by-file against the archive manifest -- and stamped -- before it is reused, since an interrupted extraction leaves short files that readers accept. Concurrent workers sharing a `dest` now coordinate via a lock instead of each downloading their own copy.
- The fire-record loaders (`load_nbac_polys()`, `load_nfdb_polys()`, `load_nfdb_points()`) and `fetch_nfdb_points()` now accept `fire_years = NULL` (the new default) to keep all years, instead of requiring an explicit year vector; pass a vector to filter. This lets callers that filter years themselves (e.g. scfm's fire-regime prep) fetch the full record in one call.
- `fetch_nfdb_points()` downloads the CWFIS National Fire Database (NFDB) fire-point archive, extracts it (caching under `dest`, so the ~1 GB archive is fetched once per location and reusable across cluster nodes), and loads it via `load_nfdb_points()` -- a single canonical NFDB fetch-and-load, replacing bespoke per-project downloaders.
- `load_nbac_polys()` and `load_nfdb_polys()` now repair invalid fire-perimeter geometries (via `spatialutils::repair_geoms()`, which passes only the invalid subset to `terra::makeValid()`) instead of dropping them, recovering perimeters (e.g. ~767 of NFDB's ~41k national polygons) that were previously discarded.
- `load_nbac_polys()`, `load_nfdb_polys()`, and `load_nfdb_points()` gain a `min_size_ha` argument (default `1`) controlling the minimum reported fire size kept; set `min_size_ha = 0` (e.g. with `load_nfdb_points()`) to retain small fires.
- `load_nfdb_points()` loads NFDB fire-point records (fire locations + reported sizes), harmonised to the same `YEAR` + `SIZE_HA` schema and clipped to the study area as the perimeter loaders, for fire-size/count summaries that do not need mapped burned-area geometry.

# fireregimetools 0.0.1

- Initial release. Arrow-native, memory-bounded fire-regime summaries, consolidating the reusable fire-side post-processing logic from the `burnSummaries` module and project pipelines (companion to nrvtools).
- `write_burn_parquet()` and `open_burn_dataset()` write and lazily read per-replicate fire tables as partitioned parquet (`replicate=<rep>/part-0.parquet`), published atomically so concurrent writers on an NFS mount never collide.
- `summarize_fire_sizes()` and `summarize_annual_area()` reduce across replicates by pushing the count + five-number summary (`min`/`q25`/`median`/`q75`/`max`, plus `mean`/`sd`/`se`/`ci`) down to Arrow compute, so the per-record rows are never all held in memory at once.
- `fire_cycle()` computes the landscape fire cycle (years) from a per-replicate annual-area-burned table.
- `fire_size_histogram()` draws the fire-size distribution (count histogram with a median-log-size-per-bin overlay on a secondary axis).
